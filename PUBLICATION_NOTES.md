# Publishing this documentation

Markdown (`.md`) is suitable for GitHub: it renders headings, tables and relative document links directly. JSON files preserve structured claims and evidence identities. There is no need to convert these files to plain text.

Upload **the contents of the `github` folder**, or extract the dedicated GitHub closeout ZIP into a new repository. This package has not been pushed or published on your behalf. It does not initialize or modify a GitHub repository.

Included: original research synthesis, a comprehensive security disposition, engineering results, corrections, a portable resume plan, source-report identifiers/hashes, sanitized final build error and reusable templates. Detailed original reports, logs and proprietary artifacts remain in the private research archive. The source index is explicit about that reproducibility limit.

Excluded: firmware archives/images, proprietary payloads, Ghidra databases, Android output trees, credentials, signing private material, device identifiers, local account names, and the machine-specific local resume note. Earlier full handoff ZIPs are not automatically publication-ready; they contain local paths and additional source/evidence files.

The included `.gitignore` helps prevent accidental future additions of large artifacts or keys. It is a convenience, not a guarantee of safe content. Review newly added files separately. Report any future confirmed security finding with its actual scope and evidence; this project did not demonstrate an unlock exploit.

No project license is assigned here because the owner has not chosen one. Decide how to license your original documentation before inviting reuse; a documentation license does not grant rights to redistribute third-party firmware or source under different terms. Existing tool/source license notices remain with their original material.

All security and CVE statements describe the archived investigation, not a fresh advisory review on the publication date. Historical source references may have changed. Claims of personal-use legality or device ownership are not substituted for technical evidence of authorization.

Keep `SHA256SUMS` with a release ZIP for integrity checking; it is a digest list, not a signed authenticity guarantee. The machine-readable claim ledger includes uncertainty and missing evidence so future readers can distinguish facts from open questions.
